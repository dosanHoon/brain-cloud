# WebM·MP4·코덱 라이선스와 GPU 인코딩 정리

## 1) 핵심 전제: 이슈는 "캡처 방식"이 아니라 "최종 코덱"
브라우저에서 캡처하든 파일 변환을 하든, 라이선스 관점 핵심은 결과 코덱이다.

- MP4는 컨테이너다.
- 실제 라이선스 이슈는 보통 H.264/H.265 코덱에서 발생한다.

## 2) 상용(사내 서비스 포함) 관점 의사결정
에셋 라이브러리 사이트처럼 업무 목적 서비스면 상용 맥락으로 보는 것이 안전하다.

- `MP4(H.264/H.265)`: 법무/라이선스 검토 권장
- `WebM(VP9/AV1)`: 상대적으로 리스크 낮음
- 최종 판단은 조직 법무 정책 기준으로 확정

실무 포인트: "내부용이니까 괜찮겠지"로 가면 나중에 정리 비용이 커진다.

## 3) 웹 배포에서 무엇이 더 낫나?
목표에 따라 다르다.

- 호환성 최우선: MP4(H.264)
- 라이선스 리스크 완화: WebM(VP9/AV1)

이번 프로젝트처럼 라이선스 민감도가 높으면 WebM 중심 전략이 맞다.

## 4) GPU 인코딩을 써도 라이선스가 자동 해결되진 않는다
"GPU로 인코딩하면 법적 이슈가 사라진다"는 오해가 많다.

- GPU/NVENC는 인코딩 방식(하드웨어 가속)일 뿐
- 라이선스는 코덱 특성에 따라 별도 고려 대상

## 5) WebM에서 GPU 인코딩 현실
WebM 주력 코덱은 `VP8/VP9/AV1`이고, GPU 가속에서 실무적으로 의미 있는 방향은 AV1이다.

- 권장 방향: AV1 하드웨어 인코더(`av1_nvenc`, `av1_qsv`, `av1_amf`)
- 제약: RTX 2070은 AV1 하드웨어 인코딩 미지원
- 결과: RTX 2070 환경에서는 WebM을 주로 `libvpx-vp9`(CPU)로 처리하게 됨

## 6) 왜 VP9가 느리게 느껴지나?
VP9는 압축 효율이 좋은 대신 CPU 부하가 크다.

- 품질 고정 시 인코딩 시간이 길다.
- 대량 배치에서는 코어 수보다 파라미터/병렬 전략 영향이 커진다.

## 정리
- 라이선스 안전성 우선이면 WebM 유지가 합리적
- 속도 문제는 코덱 변경보다 먼저 파라미터/병렬/하드웨어 전략으로 푸는 것이 현실적
- MP4 추가는 "기술 가능"과 "법적 허용"을 분리해서 검토해야 한다.
