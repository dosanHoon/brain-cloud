# 웹에서 캔버스 프레임을 이미지로 캡처하기

Three.js 같은 WebGL 씬을 **프레임 단위로 이미지로 저장**하고, 그걸 나중에 영상(GIF/WebM)으로 묶으려면 “어느 시점에 캔버스를 읽을지”, “배경을 어떻게 넣을지”, “어떤 포맷으로 인코딩할지”를 정해야 합니다.  
실제 배치 캡처 도구에서 썼던 방식을 정리한 글입니다.

---

## 1. 캡처 시점 — 한 프레임만 진행 후 렌더

- **문제:** `requestAnimationFrame` 루프는 비동기라서, “지금 이 프레임만 캡처해라”라고 외부(Puppeteer 등)에서 호출했을 때 **그 다음 rAF가 아니라 그 순간의 상태**를 찍어야 합니다.
- **해결:**  
  - “캡처 모드”일 때는 **애니메이션을 한 스텝만 진행** (`mixer.update(delta)` 한 번)  
  - 그 다음 **카메라·컨트롤 업데이트** 후 **renderer.render(scene, camera)** 한 번 호출  
  - 그 직후에 **캔버스에서 toDataURL** 호출  
  이렇게 하면 rAF 루프와 무관하게 “현재 상태 1장”을 일관되게 얻을 수 있습니다.

---

## 2. WebGL 캔버스에서 이미지 뽑기

### 2.1 렌더러 생성 시 꼭 넣을 옵션

WebGL 컨텍스트는 **기본적으로 프레임 끝에 버퍼를 비우기** 때문에, `toDataURL`을 호출하는 시점에는 이미 빈 화면이 될 수 있습니다.  
또한 **alpha 채널**이 있으면 브라우저/인코더에 따라 결과가 달라질 수 있어, 영상으로 쓸 때는 불투명 배경을 전제로 두는 편이 안정적입니다.

| 옵션 | 권장값 | 이유 |
|------|--------|------|
| **preserveDrawingBuffer** | `true` | 버퍼를 지우지 않아서, `render()` 직후 `toDataURL`로 읽었을 때 내용이 그대로 남아 있음. 안 주면 캡처가 빈 이미지나 이전 프레임이 나올 수 있음. |
| **alpha** | `false` | 불투명 배경. 투명 영역이 생기지 않아 인코딩·합성 시 예측 가능. |

```js
const renderer = new THREE.WebGLRenderer({
  canvas,
  antialias: true,
  preserveDrawingBuffer: true,  // 캡처 필수
  alpha: false,
})
```

- **preserveDrawingBuffer**를 켜면 일부 환경에서 성능 영향이 있을 수 있지만, “캡처 전용 뷰”나 “한 프레임만 렌더 후 읽기” 패턴에서는 보통 허용 가능합니다.

### 2.2 toDataURL 포맷

- **renderer.domElement**가 Canvas이므로, `canvas.toDataURL(mimeType, quality)` 로 데이터 URL을 만들 수 있습니다.
- **지원 포맷:**  
  - `image/webp` — 용량 대비 품질이 좋아서 **프레임 시퀀스 캡처에 많이 씀**. quality 0~1.  
  - `image/png` — 무손실. 투명 배경이 필요할 때나 WebP 미지원 환경 대비용.

```js
// 예: WebP 기본
const dataUrl = canvas.toDataURL('image/webp', 1)

// 예: 옵션에 따라 분기
const mimeType = options?.mimeType === 'image/png' ? 'image/png' : 'image/webp'
const quality = typeof options?.quality === 'number' ? Math.max(0, Math.min(1, options.quality)) : 1
return canvas.toDataURL(mimeType, quality)
```

## 3. 배경색이 투명이 아닌 “합성 캔버스”

- WebGL 기본 배경이 **투명**이면, toDataURL 한 이미지가 투명 영역을 갖습니다.  
  영상으로 인코딩할 때는 보통 **불투명 배경**이 필요합니다.
- **방법:**  
  - **2D 캔버스** 하나 더 만든다.  
  - 크기를 WebGL 캔버스와 동일하게 맞추고, `fillStyle`로 원하는 배경색(예: `#a0a0a0`)을 채운 뒤  
  - `drawImage(webglCanvas, 0, 0)` 으로 WebGL 결과를 그 위에 그린다.  
  - 이 **합성 캔버스**에 대해 `toDataURL('image/webp', quality)` 를 호출하면, 배경이 포함된 불투명 이미지를 얻을 수 있습니다.
- 합성 캔버스는 한 번 만들어 두고, 크기가 바뀔 때만 resize해서 재사용하면 성능에 유리합니다.

## 4. 브라우저 밖에서 캡처하기 — window API 노출

- **Puppeteer** 같은 헤드리스 브라우저에서 “한 프레임씩 캡처”하려면, 페이지 안에서 **전역 함수**를 하나 노출하는 방식이 편합니다.
- 예: `window.captureNextFrame = async (options) => { ... advance one frame ... render ... return composite.toDataURL('image/webp', quality) }`
- Puppeteer에서는 `page.evaluate(() => window.captureNextFrame({ mimeType: 'image/webp', quality: 1 }))` 로 호출하고, 반환된 **data URL 문자열**을 Node에서 `Buffer.from(dataUrl.slice('data:image/webp;base64,'.length), 'base64')` 로 디코딩해 FFmpeg 등으로 넘길 수 있습니다.
- “캡처 준비 완료” 여부는 `window.captureReady`, 에러 메시지는 `window.captureError` 같은 플래그로 두면, `page.waitForFunction(() => window.captureReady || window.captureError)` 로 대기할 수 있습니다.

---

## 5. “모션 끝” 감지

- 애니메이션이 **한 사이클 끝**났는지 알려면, mixer의 클립이 루프가 아닐 때 `action.time >= clip.duration` 또는 `action.getClip().duration` 기준으로 체크할 수 있습니다.
- 이걸 `window.isMotionFinished` 같은 값으로 두면, 배치 스크립트에서 “한 프레임씩 캡처하다가 isMotionFinished면 스트림 종료” 같은 로직을 짤 수 있습니다.

---

## 6. 실전 팁

- **Warmup 프레임:** 캐릭터가 처음 등장할 때 포즈가 안정되기 전 몇 프레임은 버리고, 그 다음부터 캡처하면 품질이 안정됩니다. (예: 처음 15프레임 discard.)
- **고정 해상도:** 배치 캡처 시에는 뷰포트를 고정(예: 960×507)하고 deviceScaleFactor=1로 두면, 프레임마다 크기가 일정해 인코딩이 단순해집니다.
- **에러 처리:** toDataURL이 실패할 수 있으므로, WebP 미지원 시 PNG로 fallback하는 코드를 두면 호환성이 좋아집니다.
